## AEE-407 — Model Context Protocol (primer)

**Length target:** ~1500-1800 words.

### Context (~250 words)

What MCP is: an open protocol that standardizes how a host (Claude Code, Claude Desktop, Cursor, an SDK harness) connects an LLM to external tools, resources, and prompts via JSON-RPC over a duplex channel. Position: agent-to-tool plane, orthogonal to A2A (agent-to-agent, AEE-608) and AG-UI (agent-to-UI, AEE-610). Spec is governed by the MCP working group; current revision at time of writing is 2025-06-18 (re-verify at writing time and update if a newer revision has shipped).

### Design Think (~300 words)

The host/client/server triangle and why the protocol separates them. Capability discovery as the central mechanic: the host asks the server what tools, resources, and prompts it offers, then advertises them to the LLM. Why JSON-RPC and why duplex — server-initiated requests for sampling and elicitation require a duplex channel; a request/response-only channel cannot support them. Relationship to AEE-401 function calling: function calling is what the LLM emits; MCP is how a host sources the tool definitions and routes the calls. The two compose.

### Deep Dive — Primitives (~400 words)

The four primitives:

- **Tools** — model-invokable functions with JSON-Schema parameters. The bulk of practical MCP use.
- **Resources** — host-attachable read-only data the model can reference (file contents, query results, doc snippets).
- **Prompts** — server-supplied prompt templates the user or host can select.
- **Sampling and elicitation** — server-initiated upward calls. Sampling lets a server ask the host to run an LLM completion on its behalf; elicitation lets a server ask the user a question mid-tool-call. Both require the duplex channel and stateful sessions.

### Deep Dive — Deployment, briefly (~200 words)

Two transports exist: stdio (host spawns the server as a subprocess) and Streamable HTTP (server runs independently, host connects by URL). One minimal `.mcp.json` example for each. Default to stdio. Link to AEE-408 for the full tradeoff (auth, latency, cost, stateful sessions, failure modes, hybrid pattern).

### Best Practices (~250 words)

When MCP earns its keep vs when a CLI is enough — Stance 2 from brainstorming:

- MCP wins on (a) reuse across many sessions, (b) structured results that downstream tool calls consume, (c) sampling/elicitation needs, (d) shared surface across multiple agents.
- A Bash tool with a CLI wins on one-off, low-reuse, low-structure capabilities where token economics dominate.

Cite the practitioner concern from AEE-3 honestly. The "every token fights for its place in the prompt" framing is a real consideration, and large MCP tool surfaces do consume context. Show that as a constraint to weigh, not a strawman to dismiss.

### Examples

## AEE-408 — Local vs Remote MCP Deployment

**Length target:** ~2200-2600 words.

### Context (~200 words)

Opens with one sentence pointing back to AEE-407 for protocol context. States the question this article answers: once a reader has chosen MCP, where does the server actually run, and how do they decide? Frames the choice as transport (stdio vs Streamable HTTP) and notes upfront that the real decision is operational (lifecycle, reach, auth, cost). Both transports surface the same primitives.

### Design Think (~300 words)

The lifecycle distinction as the load-bearing idea: stdio binds the server's life to the host process; HTTP makes them independent. Auth, latency, multi-host sharing, state persistence all fall out of that one difference.

Decision shortcut adapted from the source:

1. Does the server need local resources you can't replicate remotely? → local.
2. Does state need to persist across host sessions, or be reachable from multiple devices? → remote.
3. Otherwise → local until #1 or #2 changes.

Going remote is a one-way operational ratchet. Going local is reversible by changing `.mcp.json` and starting the server differently.

### Deep Dive — stdio (~350 words)

What happens when the host starts: config shape, `child_process.spawn`, stdin/stdout as the JSON-RPC channel, stderr reserved for logging, the `initialize` handshake. Lifecycle: SIGTERM on host exit. Stdio-specific failure modes:

- *Stdout corruption* — anything not a JSON-RPC frame on stdout breaks the host's parser. Always log to stderr; never `console.log` from a stdio MCP server.
- *No auto-reconnect* — Claude Code does not auto-reconnect stdio servers. Re-attach manually via `/mcp`.
- *cwd and PATH resolution* — relative paths in `args` resolve from the host's cwd; `command: "node"` requires `node` on PATH from the host's perspective, which differs from a shell-launched session.

Two config recipes: basic stdio, stdio with env vars.

### Deep Dive — Streamable HTTP (~450 words)

What happens when the host starts: no spawn, server must already be running, `initialize` over HTTP POST, optional SSE upgrade for streaming server-to-client messages. Optional separate GET-based SSE channel for unrelated server-initiated messages; server may decline with HTTP 405. Lifecycle independence: the server outlives the host.

Stateless vs stateful sessions:

- **Stateless** — each HTTP request creates a fresh server instance, handles the request, tears down. Works when tools don't accumulate per-session state, when backing state lives in an external store, and when server-initiated notifications aren't needed.
- **Stateful** — server returns `Mcp-Session-Id` on `InitializeResult` (exact spec casing). Clients echo it on subsequent requests. Server may terminate with HTTP 404 forcing re-init; clients can DELETE to end. Required for streaming tool results, sampling, elicitation, server-side per-session caches, and `Last-Event-ID` resume after a network drop.

`MCP-Protocol-Version` header required on every post-init request; servers without it SHOULD assume `2025-03-26` for backwards compatibility.

Backwards-compatibility note: `type: "sse"` for legacy 2024-11-05 servers; `type: "http"` for current servers. New servers should use `"http"`.

### Deep Dive — Auth tiers (~350 words)

Why local has implicit auth (host runs as you, server runs as you, no one else is on the pipe) and remote does not (the protocol is now exposed over a network beyond your machine). Five tiers ordered by friction and threat-model fit:

1. **Bearer token in `headers`** — simple, static, supported by the SDK. Total compromise on either side until rotation.
2. **Capability tokens** — short-lived, scoped, issued at session start. More plumbing, better blast radius.
3. **Platform OAuth** — Cloudflare Access, Tailscale, Auth0. Outsources auth to a provider. Right for team use, overkill for solo.
4. **mTLS** — strong guarantees, painful UX. Reserve for compliance contexts.
5. **IP allowlist** — viable only if you connect from a known static IP (rare for real users).

DNS-rebinding warning: per the MCP spec, HTTP MCP servers MUST validate the `Origin` header on incoming requests, and local-only HTTP servers SHOULD bind to `127.0.0.1`, not `0.0.0.0`. Without these protections, an attacker can drive a local MCP server from a remote website via DNS rebinding.

### Deep Dive — Latency, cost, reliability (~300 words)

Latency: stdio at microseconds; HTTP at network RTT (Cloudflare US-to-US edge tens of ms; tunneled workstation 50-150ms with reconnects; cross-region VPS 100-300ms).

Cost (re-verify at writing time; the figures below are stamped from source as of December 2025 and pricing drifts):

- Cloudflare Workers Paid: $5/mo flat; included tier 10M requests/mo and 30M CPU-ms; overage $0.30 per million requests, $0.02 per million CPU-ms. Durable Objects on Workers Paid include 1M requests + 400K GB-seconds/mo; WebSocket Hibernation eliminates duration billing while connections are idle.
- AWS Lambda: low-volume use can land near zero with non-trivial cold-start latency.
- Self-hosted on a workstation or Pi: electricity only.

Reliability: stdio servers do NOT auto-reconnect in Claude Code; HTTP/SSE retries with exponential backoff up to five attempts (one second, doubling). Long-held SSE on Lambda hits the 15-minute wall-clock cap; on Cloudflare Workers, held-open SSE doesn't bill duration under Durable Objects WebSocket Hibernation, and Workers don't cap wall-clock for HTTP-triggered requests.

The chattiness rule: 30ms × 50 calls = 1.5s of pure transport overhead per session. Matters for chatty servers; lost in noise for low-volume tools.

### Best Practices (~200 words)

The hybrid pattern from the source: one server process supporting both transports, where local-vs-remote becomes a deployment switch rather than an architectural rewrite. The MCP SDK ships transports for both stdio and Streamable HTTP; mounting both is an additive change.

Default to stateless HTTP; graduate to stateful when a feature requires it. Default to stdio overall; graduate when there's a real reason.
